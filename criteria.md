# Writing criteria for this guide

Every "for Mere Mortals" guide is written to the same nine-point
standard, so a reader who trusts one can trust the rest. Here it
is, with the verification notes for this particular guide below.

1. **Fix it first.** Reader outcomes lead, not action items: each
   chapter opens by naming the outcome it delivers, shows a check
   the reader can run to confirm they got it, and a reasonable
   reader finishes able to state what was done, what it means,
   and what to try next.
2. **Plain language.** Short sentences, everyday vocabulary,
   technical terms defined on first use. No slang, and no
   idioms that only make sense in one country — the reader may
   be translating as they go.
3. **No dead ends.** A guide never tells the reader to do
   something it cannot show them how to verify. Every claim a
   reader relies on — an install, a command, an output — is
   something this guide demonstrates or clearly labels
   documented-only below.
4. **Live-verified where it matters.** Procedures are run for
   real in the guide's lab wherever the build machine allows it,
   and the transcripts kept in the repository are the evidence.
   What could not be run is listed honestly below, never
   presented as if it had been.
5. **General audiences.** Nothing in this guide — examples,
   fixtures, names, addresses — is modelled on any particular
   reader or author's real life, network, or organisations.
   The lab's feeds are invented journals about gardening,
   cooking and hand tools, served from the lab's own machine.
6. **Standalone.** A reader needs this guide, its lab, and
   nothing else. Where another guide would genuinely help, it
   is pointed to once, by name, and the chapter still completes
   without it.
7. **Honest about limits.** Chapter 13 names what the tool
   cannot do: no sync of its own, articles that are only what
   the feed carries, command-line reloads that fail in silence,
   read state set at the moment of opening, a query-feed count
   that always shows (0/0), and cleanup controls whose names
   promise more — or other — than they do.
8. **The ethics rule is in the text, early.** Newsboat raises a
   privacy question rather than an interception one, and the
   README and chapter 1 state its line plainly, before any
   procedure depends on it: the cache is a reading diary that
   stays on the user's own disk, the tool itself phones nowhere
   and keeps no account, and fetching a feed tells that feed's
   publisher an address fetched it, and when — nothing more
   is sent, and nothing is hidden either.
9. **Builds clean.** The site builds with MkDocs in strict mode
   with no warnings, and a fresh reader following the chapters
   in order reaches the stated outcome of each.

## Verification notes for this guide

The build machine is a 2-CPU, 7.7 GB Ubuntu 24.04 sandbox,
shared with other work while the lab ran. Ubuntu 24.04 (noble)
carries **no newsboat package** — verified three ways: against
the release's raw universe package index (the only occurrence
of the word is a `Recommends` inside an unrelated package),
through `apt-cache policy newsboat` after a full update
(`Candidate: (none)`, t00), and by the absence of the package
in every noble pocket index. Newsboat **2.34.1** was therefore
built from the project's official release tarball
(`newsboat.org/releases/2.34.1/`, SHA-256
11edb139…df708a), unmodified, with the distribution's cargo
1.75.0 and the development libraries its README names. The
newer release current at lab time (2.45, seen in the project's
own release feed, t14) declares Rust `edition = "2024"` in its
manifests, which the sandbox's Rust 1.75 cannot compile —
that, and nothing else, is why the lab ran 2.34.1. The build
took about six and a half minutes with `make -j2`; the
binaries were run from the build tree rather than installed
system-wide, which the install chapter states.

All lab feeds were fixtures invented for this guide, served by
Python's `http.server` on loopback port 18089: an RSS 2.0
gardening journal (8 items), an Atom kitchen journal (4
entries), a podcast (2 items with WAV enclosures — one-second
sine tones generated by the lab), and one deliberately
malformed feed. Every article link in the fixtures resolves to
a page on the same fixture server (two hand-written, the rest
generated from the feeds by `make-pages.py`). One real public
feed — the project's own GitHub releases Atom feed — was also
subscribed and reloaded (t14) to prove the same commands work
against the live internet. Transcripts live in
`newsboat-lab/transcripts/`; interactive sessions were driven
through a real terminal emulator and rendered from its screen,
with the selected row marked `>>`.

Run for real, with transcripts as evidence:

- The missing noble package, the dependency set, the tarball
  hash, the build, and `--version`/`--help` output (t00).
- The fixture server checks and the subscriptions file (t01);
  the first command-line reload, `print-unread` (14 unread),
  and per-feed cache counts matching the feeds exactly (t02).
- The reading session: feed list, article list, opening an
  article and watching all three counts step down, the save
  dialog and its suggested filename (t03).
- The browser handoff, proven by a script that records the
  exact URL it was handed (t04), and the same `o` key opening
  the article's page in the real text browser **w3m** 0.5.3
  and returning (t05).
- OPML import of a fixture file (folders became tags), reload
  of the imported set (12 unread), plain OPML export (tags
  absent), and OPML 2.0 export (tags present as categories)
  (t06).
- Slash search for a word appearing in one title and one body
  (2 results, read state respected) (t07).
- A query feed (`unread = "yes" and feedtitle =~ "Garden"`):
  its (0/0) count in the feed list, its 8 matching articles,
  and one article dropping out of it after being read (t08).
- The bookmark prompts and the bookmark script receiving all
  four documented arguments into a text file (t09).
- A macro (`macro R mark-all-feeds-read`) firing its
  operation, including the confirmation prompt, with
  `print-unread` agreeing afterwards (t10).
- `max-items 3` keeping exactly the three newest of eight
  articles in a fresh cache (t11).
- Both cleanups, semantics first checked in the 2.34.1 source:
  `cleanup-on-quit` (default yes) removing an unsubscribed
  feed's rows 14 → 12 on quit, `--cleanup` doing the same job
  on demand (12 → 8), and `delete-read-articles-on-quit`
  flagging all 14 read rows `deleted = 1` while removing none,
  the flagged articles invisible on reopen (t12).
- Podcast queueing (the `e` key and the queue file's exact
  line), Podboat downloading on `d` — not automatically — to
  the configured `download-path`, the file byte-identical in
  size to the enclosure's promise, and the queue line gaining
  `downloaded` (t13).
- Failure behaviour: the malformed feed (channel title kept,
  zero items, "Error: feed contains no items!" on opening),
  the 404 feed (raw URL in the list), and the command-line
  reload staying silent with exit 0 throughout (t15).

Documented only — described from the project's documentation,
not run, and the text does not claim otherwise:

- Reading through remote accounts (FreshRSS, Miniflux,
  Nextcloud News, Feedbin and the other backends), including
  Newsboat standing in front of a FreshRSS or Miniflux server.
- Config surface beyond the settings the lab set: colours,
  display formats, `bind-key`, sort orders, the external
  editor, and the full filter-field table beyond the two atoms
  the lab ran (`unread`, `feedtitle` with `=~` and `and`).
- `--vacuum`, Podboat's purge/play operations, and cron
  scheduling of the reload (the command form was run; the
  crontab line is the same command on a schedule).
- The neighbour tools of chapter 12 — characterised, with the
  FreshRSS and Miniflux behaviour resting on this series' own
  guides for those servers.

Two lab incidents are recorded where a reader would meet them:
the save dialog's pre-filled filename once swallowed the name
the operator typed after it (chapter 5), and an invented config
setting was refused at startup by name (chapters 2 and 14). An
early cleanup experiment built on a wrong reading of
`cleanup-on-quit` was caught by reading the source and re-run
correctly (t12); the wrong version was not published.
